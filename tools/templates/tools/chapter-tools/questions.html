{% comment %} Records, not a table. This was a 6-column data-table and it was the worst instance of the pathology index.html already documents: column 1 held full-sentence question prose while columns 5 and 6 each held an inline form with a text input. .page-card sets overflow-x:auto and table auto-layout gives a prose column its max-content width, so the two inputs - the only controls on the page - were squeezed to a few characters wide. Inputs are worse than prose here because they do not wrap; they just become unusable. A record reads top-down and has no column budget to overrun, so it is readable at 375px and at desktop. The .record-* vocabulary lives in components/_chapter-tools.css, because the Tailwind CLI cannot run on this machine and a width-responsive layout is not expressible with the six md: utilities that happen to be compiled. Comment BLOCK tag, not the short hash-brace form: that form is single-line only in Django, so a multi-line one renders to the page as literal text. {% endcomment %}
