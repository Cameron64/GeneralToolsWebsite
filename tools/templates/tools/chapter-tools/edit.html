Nine separate pages would be nine round trips on a phone, and the whole reason this page exists is that the registry was previously editable only through /admin/. The sections are TABS rather than stacked cards. Stacked, every child row is added on its own page which redirects back here, so adding a second holder meant landing at the top of the page and scrolling down past a list that had just grown by one - once per row. The active tab lives in ?tab= exactly so the child views can redirect into it (see _backToSection in chapterToolsViews.py), which is what removes that scroll. Tabs held in CSS or JS state could not do it; the tab has to survive a round trip. Links, not role="tab" - see components/_tabs.css for why. Single column at every width, and the child rows are .record-item cards rather than a table - see components/_chapter-tools.css for why a table cannot work here. hasAudit gates the restricted layer. The template guard is the SECOND line of defence, not the first: the view already omits the credential rows and the RUNS_ON edges from the context, so a guard removed here still cannot render them. _activeTab applies the same rule to the tab strip, so a hand-typed ?tab=credentials lands on holders instead.
